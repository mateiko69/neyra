# NEYRA fix audit — 2026-04-24

## Applied fixes

1. Backend Python syntax blocker
   - Fixed a broken f-string in `backend/app/api/v1/endpoints/ai.py` that prevented the backend package from compiling.

2. Public verification badge safety
   - OAuth/social login no longer marks a profile as publicly verified.
   - Public verified state now consistently means: `profile.verified == true` AND `profile.verification_status == "approved"`.
   - Partner profile output now uses the same approved-verification rule.
   - Verification submit/reject paths now clear `verified` and `verified_at` when status becomes `pending` or `rejected`.

3. Verification attempt race protection
   - Added IntegrityError-safe get-or-create logic for daily verification attempt counters.
   - This reduces duplicate-row/race bugs when a user submits verification more than once quickly.

4. Social login integrity handling
   - Added safe IntegrityError rollback for OAuth linking/creation.
   - This prevents raw DB errors if the same OAuth identity is linked concurrently.

5. Frontend API resilience
   - Added two retry attempts with exponential backoff for transient pre-response network failures in `frontend/lib/api.ts`.
   - Abort/cancelled requests are still treated as cancellations, not as API outages.

6. Tests updated
   - Updated social-login test expectations so OAuth email verification does not grant the NEYRA public verified badge.
